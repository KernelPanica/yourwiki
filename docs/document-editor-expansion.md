# Расширение редактора документов

Этот документ фиксирует проверку текущего кода и варианты реализации запроса на возможности Google Docs / Word. Это проект следующего изменения, а не отчёт о внедрении новых функций.

## Что уже работает

Редактор внутри интерфейса Yourwiki использует Tiptap / ProseMirror и Yjs. Есть шрифты и размеры текста, заголовки 1–6, начертания, цвета и выделение, выравнивание, четыре варианта межстрочного интервала, списки и их вложенность, ссылки, таблицы с объединением ячеек, заливкой и заголовками, вставка изображений и изменение их ширины, структура документа, масштаб, поиск и замена, статистика, комментарии, предложения и совместное редактирование.

DOCX импортируется и экспортируется через `wiki/docx.py`. Редактор, серверная валидация, HTML-предпросмотр и DOCX-конвертация должны поддерживать одну структуру документа.

## Пробелы, обнаруженные в коде

| Область | Текущее ограничение | Критерий готовности |
| --- | --- | --- |
| Абзацы | Отступы работают только для вложенности списков | Левый и правый отступ, первая строка, интервалы до/после сохраняются и повторно открываются |
| Страницы | Разбиение визуальное; размер бумаги фиксирован | Размер, ориентация, поля, ручные разрывы и разделы соответствуют DOCX и печати |
| Колонтитулы | Нет модели и инструментов | Редактирование верхнего/нижнего колонтитула, номера страниц, отдельная первая страница |
| Сноски | Нет модели | Вставка, изменение, удаление, последовательная нумерация и DOCX round-trip |
| Оглавление и ссылки | Есть только боковая структура | Оглавление в документе, закладки, внутренние ссылки, обновление по заголовкам |
| Текст | Нет надстрочного/подстрочного текста и настройки регистра | Команды действуют на выделение и сохраняются в DOCX |
| Поиск | Замена всех совпадений внутри отдельных текстовых узлов | Навигация по совпадениям, замена одного/всех, поиск через границы начертаний, параметры регистра |
| Списки | Ограниченные стили и вложенность | Стартовое число, продолжение/перезапуск нумерации, стили маркеров |
| Изображения | Есть вставка и ширина; стандартный экспорт DOCX не записывает изображения | Встроенные изображения импортируются и экспортируются как медиа DOCX; размер, подпись и расположение сохраняются |
| Таблицы | Есть базовая структура, заливка и объединение | Ширины колонок, границы, отступы ячеек и вертикальное выравнивание сохраняются |
| Исправления | Комментарии и предложения — отдельная модель Yourwiki | Ясный контракт переноса комментариев и исправлений между редактором и DOCX |
| Проверка текста | Нет отдельного средства проверки языка | Проверка орфографии с выбором языка; дополнительные средства требуют отдельного решения |
| Дополнительные объекты | Нет уравнений, диаграмм, фигур и сложных полей | Каждая включённая возможность имеет рабочее редактирование, хранение и экспорт |

Равенство всем возможностям настольного Word нельзя считать выполненным по внешнему виду панели или количеству кнопок. Для выбранного набора возможностей нужны проверяемые сценарии редактирования и открытия в другом офисном приложении.

## Варианты реализации

### Развивать текущий редактор

Сохраняет текущую установку одним сервисом, общие Yjs-сессии и интеграцию комментариев. Для каждой возможности требуются изменения схемы Tiptap, серверной валидации, DOCX-импорта/экспорта и предпросмотра. Сложная вёрстка страниц, разделы, сноски и плавающие объекты требуют отдельных существенных подсистем.

Порядок: сохранность изображений и абзацев → текст/списки/поиск → страницы/разрывы → таблицы/изображения → колонтитулы/сноски/оглавление → дополнительные объекты. Возможность считается завершённой после сохранения, повторного открытия, совместного редактирования и проверки read-only.

### Встроить офисный движок

Добавляет отдельный офисный сервис и интеграцию внутри оболочки Yourwiki. Рассматриваются ONLYOFFICE Docs и Collabora Online; выбор зависит от основного формата и эксплуатационных ограничений. Набор возможностей определяется конкретным движком и его редакцией, а не обещанием полного соответствия Word.

Для ONLYOFFICE нужны выдача конфигурации и файла, проверяемые JWT, общий ключ активной сессии и callback сохранения. Совместное редактирование выполняет офисный движок. Одновременно писать один DOCX через него и через существующую Yjs-сессию нельзя.

Для Collabora требуется WOPI-интеграция с проверкой пользователя, доступа, блокировок, версии и записью файла.

В обоих вариантах:

- Оболочка, проводник, настройки файлов и права остаются в Yourwiki.
- Документ выдаётся движку через проверяемый серверный маршрут; токены провайдера не передаются браузеру или офисному сервису.
- Перед каждой записью проверяются доступ и версия оригинала. При внешнем изменении сохраняется отдельная копия конфликта.
- Сохранение проходит через существующие адаптеры и модель восстановления неопределённого результата.
- Нужно определить перенос существующих комментариев и предложений, историю, presence и поведение старых активных сессий.
- Для Markdown и нативных документов провайдеров нужен отдельный маршрут; интеграция DOCX не доказывает поддержку этих форматов.
- Проверяются ограничения выбранной редакции, возможность встраивания, лицензия, ресурсы сервера и поведение мобильного интерфейса.

Официальные описания интеграции: [совместное редактирование ONLYOFFICE](https://api.onlyoffice.com/docs/docs-api/get-started/how-it-works/co-editing), [callback сохранения](https://api.onlyoffice.com/docs/docs-api/usage-api/callback-handler), [защита запросов](https://api.onlyoffice.com/docs/docs-api/get-started/how-it-works/security), [Collabora SDK](https://sdk.collaboraonline.com/CO-SDK-manual.pdf).

## Решения, которые определяют реализацию

1. Отдельный офисный сервис или развитие текущего редактора без дополнительных сервисов.
2. Word/DOCX или Google Docs как основной образец поведения.

После выбора нужен конкретный перечень возможностей и приёмочных сценариев. Для офисного сервиса также нужна проверка ресурсов и лицензии до изменения рабочей установки.
