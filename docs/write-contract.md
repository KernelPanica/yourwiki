# Запись и восстановление

Все адаптеры возвращают фактический reference после подтверждения провайдером.
`fingerprint(reference, bytes)` обозначает подтверждённую версию: SHA-256 байтов,
а для нативной Google Sheets — хеш версии Drive, полученной после batchUpdate.
`StorageRejected` означает отказ **до изменения оригинала**. Обычная ошибка,
таймаут или потеря соединения этого не гарантируют.

Перед отправкой основной записи Yourwiki синхронно сохраняет намерение и байты
в `DATA_DIR/write-journal/<document UUID>/`. Файлы имеют права 0600, каталоги
0700; payload и метаданные публикуются атомарно с fsync. Этот каталог требуется
сохранять вместе с базой и не удалять при обновлении контейнера. Он содержит
неподтверждённые документы и требует того же режима доступа, что резервная копия.
WriteAttempt хранит индекс подтверждения в SQL; файловый журнал переживает
откат SQL после успешной удалённой записи.
Перед переименованием отдельно сохраняется `moves.json` с исходным и ожидаемым
reference и контрольной суммой. Потеря ответа на rename и откат SQL после rename
восстанавливаются чтением обоих адресов, в том числе когда содержимое не менялось.

После неопределённого результата SaveSession остаётся в состоянии `unknown`,
сохраняет payload и приостанавливает автоматические попытки. Ручное сохранение
сначала читает оригинал:

1. Совпадает с ожидаемой исходной версией — можно повторить запись.
2. Совпадает с намерением — подтверждается предыдущая запись без повторения
   структурных операций. Для Google Sheets сравниваются видимые значения,
   формулы, поддерживаемые стили, размеры, порядок листов и объединения.
3. Отличается от обоих — конфликт; перезапись не выполняется. Доступны выгрузка,
   копирование и явная перезагрузка с отказом от локальных изменений.

Подтверждение каталога и SQL receipt записываются одной транзакцией. Новые правки,
полученные после неопределённого результата, применяются к подтверждённой версии,
а не повторяют старый пакет. Потеря ответа на создание, когда reference неизвестен,
останавливается для административного разбора; автоматически создавать второй
объект небезопасно. Журнал содержит имя объекта, UUID документа и исходные байты.

## Границы гарантий

| Провайдер | Запись |
| --- | --- |
| Local | Завершённый временный файл и атомарный replace |
| SMB | Замена завершённого временного файла |
| SFTP | posix-rename; сервер без расширения отклоняет замену |
| Google Drive | Upload в существующий объект; Google Sheets — один атомарный batchUpdate со стабильными sheetId |
| OneDrive | Upload в существующий объект |
| GitHub | Contents API с SHA версии и собственная история Git |

Проверка fingerprint перед записью и транзакция SQLite сериализуют записи
Yourwiki в поддерживаемом развёртывании с одним ASGI-процессом. Это не общая
атомарная compare-and-swap относительно сторонних клиентов: внешнее изменение
между проверкой и запросом не исключено для API без условной записи. Google
batchUpdate атомарен внутри пакета, но не относительно проверки версии Drive.
Для нескольких процессов нужна отдельная распределённая блокировка writer.

История и переименование выполняются до основной записи. При заведомом отказе
их изменения откатываются насколько позволяет провайдер. При неопределённом
результате они сохраняются для разбора и восстановления; безусловный откат мог
бы повредить уже записанный оригинал. Отдельный PDF-слой создаётся как новый
неизменяемый объект и никогда не перезаписывает базовый PDF; прерванная публикация
может оставить неиспользуемый объект слоя. Автоматическая очистка таких объектов
не выполняется.
