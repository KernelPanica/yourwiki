`GoogleConnectStates.begin` requires an actual current Gigaadmin session and its valid CSRF token, enabled Google connection and current configuration revision. It needs configured client ID/secret/root, not an existing refresh token. It returns only a fixed Google consent URL and expiration. The URL requests offline Drive access and S256 PKCE with a random256-bit verifier; it never includes the client secret. Raw state is random256-bit, stored only as SHA256. The encrypted verifier envelope binds exact state hash, user, initiating browser session hash, connection/revision, configured callback and current root/client identity. Session cookies, raw state and verifier are not stored in plaintext in this table.

Append-only schema40 retains pending/claimed states for at most10minutes and never beyond the initiating session expiry. Identity/encrypted context is immutable; claimed cannot return to pending. There is no FK to the sessions table that could prevent ordinary logout. Live session/auth-version/role/CSRF are checked again at claim and while using the private credential lease. The same user in another browser session cannot consume state. Expired entries are pruned in a bounded batch on begin; all retained entries, including claimed ones, count toward four per user and256 total. A claimed state cannot be reset to bypass capacity or retry code exchange.

Claim is atomic and one-shot across DB handles/reopen. It yields a private checked credential lease for later code exchange, never an HTTP credentials DTO. Current client secret, client ID, root, enabled state and revision remain pinned. Unrelated refresh-token rotation does not invalidate a pending consent flow; changing client identity does. Unknown original connection settings remain untouched. No token is exchanged, refreshed or persisted by this component.

Callback origin is trusted configuration, never a request Host/Origin/redirect parameter. HTTPS origins are required except explicit localhost/loopback HTTP for development. Userinfo, path, query and fragment are refused. The callback path is fixed `/api/admin/google/oauth/callback`. Existing login cookies are SameSite=Strict: the future callback must use a minimal same-origin completion step before consuming state rather than weakening cookie policy. The callback page must not expose a code/state to third-party assets or request logs.
