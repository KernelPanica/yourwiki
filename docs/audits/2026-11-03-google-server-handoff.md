# Google: передача серверному агенту

Статус: Google-этап **не завершён**. Этот файл отделяет написанные сценарии от отсутствующих и от приёмки настоящего провайдера. Пользователь поручил проверку реального Google другому агенту на сервере; локальные прогоны используют только собственный синтетический HTTP-провайдер.

## Что запускается

- TS/Fastify/React, существующий инициализированный v2 workspace, текущая схема 47. Миграции 1–44 неизменны; новые миграции применяются при открытии БД. Legacy Django DB этому процессу передавать нельзя.
- Веб: `npm start --prefix apps/server -- /absolute/v2.sqlite3 /absolute/private-store /absolute/existing.key https://wiki.example /absolute/web/dist --port 3100`.
- Источники: `npm run provider-worker --prefix apps/server -- /absolute/v2.sqlite3 /absolute/private-store /absolute/existing.key`.
- Предпросмотры: `npm run worker --prefix apps/server -- /absolute/v2.sqlite3 /absolute/private-store --office-root /absolute/libreoffice`. Office runtime должен быть установлен на сервере отдельно. Provider worker конвертацию не выполняет.
- Ключ должен быть исходным ключом этой тестовой установки. Не генерировать новый ключ поверх существующих зашифрованных подключений. Не выводить конфигурацию, bearer, refresh token или callback code в отчёт.
- Docker в репозитории пока запускает Django. Переключение Docker/установщик/миграция legacy находятся в следующем этапе выпуска; не выдавать текущий Docker за TS runtime.

## Готовые для серверной приёмки сценарии

1. Подключение общего Google-аккаунта через настройки Гигаадмина. В OAuth client разрешить точный callback `/api/admin/google/oauth/callback` на публичном HTTPS origin установки. Проверяются владелец и корень; личные учётные данные не заменяют центральные.
2. Поиск файлов Google, переход по папкам и страницам, импорт Docs/Sheets/Slides и обычных поддержанных файлов. При импорте сохраняется Google file ID; YourWiki публикует документ только после готового предпросмотра. Ошибка/лимит экспорта сохраняет старый готовый просмотр.
3. Личный Google-аккаунт привязывается на странице аккаунта. Для него отдельно разрешить callback `/api/google/identity/callback`. Запрашиваются только `openid email`; личный Drive refresh token не сохраняется. Внутренний просмотр YourWiki личного OAuth не требует.
4. Provider worker выводит желаемые роли из текущих наследуемых локальных ACL и доставляет `reader`/`writer`/отзыв центральным аккаунтом. Для нескольких локальных ссылок на один оригинал действует объединение прав. Ссылка только для чтения не выдаётся через локальную ссылку, если та же личность имеет writer через другой alias.
5. «Открыть оригинал» появляется после подтверждения прав и ограничений экспорта. Редирект заново проверяет текущие локальные права. Google-native editor открывается в отдельной вкладке; это **не** готовый встроенный редактор всех нативных форматов.
6. Уведомление об открытом оригинале — отдельный локальный receipt с TTL, не утверждение о живом курсоре/реальной активности Google. Закрытие уведомления не сохраняет документ. Существующие предупреждения об изменении оригинала, конфликте и сохранении буфера остаются в Office/source sync.
7. Создание Docs/Sheets/Slides/папки через настройки. Создание нативного документа не повторяется вслепую после потери ответа: объект ищется по приватной метке операции. Затем используются обычные проверенные discovery → import → preview. Папки доступны как именованные назначения.
8. Перемещение/переименование связанного документа **внутри одного подключения** сохраняет оригинальный ID и локальные версии. Пока операция не завершена, локальные сохранения и открытие Office блокируются. Перемещение между подключениями ещё не реализовано.
9. Simple/Giga могут отправить документ в корзину; явное восстановление доступно только Giga. Скрываются все локальные aliases исходного Google ID; при восстановлении возвращаются скрытые этой операцией ссылки. Содержимое и история не удаляются. Подтверждённая корзина наблюдается фоновым metadata-only заданием: восстановление в Google возвращает локальную видимость и ставит входящую синхронизацию.
10. Настройки показывают состояния доставки прав, экспорта, корзины и операций. После потери роли/сессии приватные результаты очищаются. Проверка неизвестной create/move/trash операции повторяет чтение/сверку результата, не повторяет её мутацию.

## Обязательные случаи реального Google

Использовать отдельную тестовую папку и расходные тестовые файлы, не документы пользователей. Не удалять тестовую папку автоматически при неопределённом результате.

- Импорт и реальная конвертация DOCX/ODS/PPTX из Google-native, объединённые ячейки, Unicode и длинная презентация; после изменения оригинала приходит новый просмотр.
- Reader не может редактировать оригинал; writer может. Удаление локального доступа отзывает Google permission. Публичные/domain grants не добавляются. Изменение унаследованной папочной политики не перезаписывает явное исключение.
- Запрет экспорта доставляет `downloadRestrictions.itemDownloadRestriction` и `writersCanShare=false`; сохраняются исходные ограничения для возврата после выключения политики. Отказ Google отражается в статусе, не маскируется успехом. Владелец Google и скриншоты не ограничиваются этим API.
- Два разных пользователя, несколько aliases, отозванный пользователь, отключённое подключение, лимит Google, недоступность/таймаут, перезапуск worker в каждом состоянии.
- Create/move/trash/restore: Google ID тот же; после потери ответа не появляется второй объект/второй PATCH. Ни 404, ни ошибка доступа не считаются доказательством удаления или восстановления.
- Восстановление из Google trash автоматически возвращает YourWiki. Учитывать интервалы наблюдения: ingress около 30 секунд, trash watch около 60 секунд; это не мгновенный внешний push.
- После конфликта выход из редактора ничего не сохраняет автоматически, пользователь видит предупреждение и может сохранить свои изменения. Legacy popup regression проверять в существующих Office/source sync сценариях.

## Что запрещено считать завершённым

- `createProviderResolvers(...).outgoing` по-прежнему разрешает только Local. Безопасная обратная запись обычных Google-файлов **не включена**. Журнал resumable upload и status protocol не являются работающим безопасным writer.
- Есть requiredRevisionId-протокол Docs/Slides, native snapshot/journal и ограниченный Docs text compiler. Нет полного встроенного native editor, доказанного общего OOXML↔native round-trip и полного Sheets compiler/concurrency решения. Нельзя подменять это импортом OOXML поверх Google-native: такой импорт заменяет содержимое оригинала.
- Для Drive media и Sheets batchUpdate не подтверждён требуемый CAS-контракт. Проверка версии перед записью оставляет окно гонки; произвольный `If-Match` без подтверждённой поддержки не исправляет её. Подтверждение на настоящем провайдере должно включать две конкурирующие записи и неизменность более новой версии при запоздалой старой записи.
- У permissions/export controls нет приватной метки операции/условия версии. Если сам ответ на запись потерян, совпадение прочитанного состояния не доказывает завершение запоздалого запроса. Такая операция остаётся `unknown`; противоположная запись блокируется. Если успешный ответ сохранён, а потеряно только чтение результата, повторное чтение безопасно. Не разблокировать uncertainty ручным UPDATE БД.
- Не готовы перенос между mount connections, автоматический полный импорт дерева/changes feed, общий legacy migration runner и выпуск npm Docker.
- Нет приёмки 2 CPU / 4 ГБ / 10–15 пользователей, настоящего Redmi/iOS, VPN-free availability и всей страницы за 500 ms. Локальный mobile viewport не доказывает эти требования.
