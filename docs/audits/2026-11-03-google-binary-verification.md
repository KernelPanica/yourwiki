# Google binary read composition

Internal Task3 checkpoint on top of07a40e0; production/CLI resolver remain Local-only. This is not a replacement for native Google Docs/Sheets/Slides export/editing or conditional delivery.

`GoogleBinaryReader` composes the fixed-origin metadata and content protocols. A trusted worker supplies the pinned connection root, borrowed OAuth and canonical scoped managed-recipient lookup. It verifies current ownership/permissions/root ancestry/type/size/version before returning a lazy body, consumes exact-length content, then repeats metadata validation before successful EOF. Its fingerprint keeps exact uint64 version strings and source ID/MIME/size/direct parents. Changed version/MIME/size/parents yields PROVIDER_CONFLICT; lost ownership/root/managed sharing fails verification. Native MIME is refused before alt=media, preserving the future native export boundary. Prepared bodies are single-use; shutdown fences unstarted/prepared bodies and interrupts asynchronous caller checks even before metadata HTTP starts. No automatic content replay or source write is added.

The reader is an internal component, not a public ProviderAdapter or activated resolver. Final wiring must obtain canonical DB root/reference/document format from the minted connection, never accept a browser-supplied root or silently treat Google-native content as binary. Source-format compatibility and available provider checksum/revision validators still need the final Google adapter's acceptance rules; before/after version checks are not a claim of undocumented Google transactionality. Real Google-account acceptance remains required.

It now retains a narrow set of actual typed provider read errors, including conflict/config/export-limit/quota-unavailability/access denial, in the failed private receipt and rethrows their identity. Plain untrusted errors are still normalized; arbitrary error text is not stored or returned. A changed source cannot reach the source commit. Failed namespace/quota ownership remains charged for existing recovery/cleanup rules. Source conflict gets a distinct ru/en/es warning without falsely claiming that an authenticated incoming snapshot exists; unsaved-buffer guidance remains visible.
