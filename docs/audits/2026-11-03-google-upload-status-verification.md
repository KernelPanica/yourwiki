# Google resumable upload status protocol

Task4 prerequisite on base6270b26. `GoogleUploadStatus` is private, not wired into the public provider resolver or the delivery worker yet. It cannot create a session or upload source bytes.

The probe sends one empty PUT with Content-Length0 and Content-Range `bytes */N` to a validated session capability. Only HTTPS www.googleapis.com and the exact Drive v3 upload path (generic or the bound file ID) are accepted. No credentials/userinfo, fragment, normalized path tricks, duplicate/unknown query fields, missing upload ID or control characters are accepted. Validation runs before obtaining a token. A generic session URI does not itself prove object identity: future durable session storage must bind it to the canonical attempt before this component is composed with delivery.

308 responses produce a checked received-byte count from a single contiguous `bytes=0-last` range, or zero when absent. Counts cannot exceed the declared exact file size, including zero and4GiB boundaries. 200/201 require bounded JSON identifying the exact bound file and return only a completion hint, never provider JSON or a content-confirmation receipt. 404 produces an expired hint. Redirects and changed session Locations are refused. 401 invalidates the token without replay; 403 quota reports unavailability while permission denial remains access denied. All errors are static; a session URL is never put into an error or public DTO.

The transport checks current authority around async boundaries, bounds admission to eight requests and control JSON to256KiB, and uses a maximum30s deadline. Shutdown drains admitted operations, aborts pending authority/transport/body waits and cancels late response bodies even if an injected transport ignores AbortSignal. No upload body, automatic retry, session cancellation, expiry-as-write-confirmation or unconditional source replacement is introduced.
