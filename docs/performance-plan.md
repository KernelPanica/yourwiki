# Ускорение запросов Yourwiki

Цель: существенно сократить ожидание страниц и действий, стремиться к 1–2 секундам для обычных операций, без ослабления ACL и защиты от конкурентной записи.

Выявлено: OAuth refresh перед каждым запросом провайдера; синхронный полный reconciliation прав после commit; IMMEDIATE-транзакция при сетевом чтении предпросмотра; повторное построение ACL-графа и выборка всей навигации.

Изменения:
- Токен OAuth кешируется в памяти адаптера до expires_in с запасом. Одновременные refresh объединяются, HTTP-соединения переиспользуются отдельно для каждого потока. Ошибки не кешируются как успешный результат.
- Изменение локальных ACL ставит устойчивый запрос в БД; отдельный ASGI-worker объединяет запросы, повторяет ошибки, восстанавливает работу после рестарта. Команда принудительной синхронизации остаётся доступной. В UI виден статус ожидания.
- Сетевое чтение предпросмотра выполняется без write-транзакции; короткое обновление baseline защищено условием reference/digest. Кеш успешного содержимого ограничен объёмом и сроком, ключом оригинала/digest; несохранённая совместная сессия имеет приоритет.
- ACL-граф переиспользуется только внутри одного запроса; отзыв прав виден следующему запросу без ожидания TTL.
- Проверки: число OAuth refresh, конкуренция/expiry, фоновые повторения и изменения во время reconciliation, query counts, ACL, сохранение/конфликты, замеры на сервере.

Скорость внешнего облака и холодного запуска Collabora не гарантируется. Объектные операции записи остаются защищены существующим журналом и конфликтами; не менять их транзакционную модель без отдельного доказательства безопасности.
