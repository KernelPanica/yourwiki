# Yourwiki: архитектура перехода на TypeScript

Дата: 2026-10-30. Статус: утверждён пользователем 2026-10-30 («делай пока что можешь, утверждаю»). Утверждённая дорожная карта: ../plans/2026-10-30-yourwiki-rewrite-roadmap.md.

## Назначение

Переписать веб-версию на Fastify/React с сохранением данных, функций и обновления через Git/Docker. Ускорить чтение за счёт локальных оригиналов и подготовленных представлений, отделить обработку документов и облачные операции от HTTP-запросов. Не считать смену языка достаточной оптимизацией.

Исходная реализация: e56a71e. Реестр: ../../audits/2026-10-30-feature-inventory.md. Продуктовая совместимость важнее копирования внутренней структуры Django.

## Принятые пользователем решения

- Backend TypeScript/Fastify; frontend React/TypeScript/CSS. Collabora — основной редактор офисных файлов.
- PDF.js остаётся: аннотации, формы, оригинал, слои и восстановление сохраняются.
- Canvas и локальный draw.io остаются; Dashboard, personal Recent, avatar, animation preference добавляются.
- Страница появляется с готовым preview, Collabora загружается параллельно, ввод становится доступен после её готовности без второго нажатия.
- Новые файлы доступны после подготовки preview. При обновлении сохраняется последний опубликованный вариант до готовности следующего.
- ACL принадлежат Yourwiki и кешируются локально. Передача прав Google обязательна, не блокирует страницы.
- Гигаадмин восстанавливает/удаляет окончательно; Простой админ только отправляет в корзину.
- Все уведомления/защиты от потери данных сохраняются. Выход из конфликта не инициирует запись оригинала.
- До 15 пользователей, минимум 2 CPU/8 ГБ на Yourwiki+Collabora. Task Tracker отдельно.
- Цель страниц до 1 с, идеал 0.5 с, прогретые ресурсы браузера на Redmi Note 12T; сервер в интернете.
- Требуется просмотр/редактирование файлов до 4 ГБ; реализуемость не подтверждена. Предварительный отдельный эксперимент отменён пользователем. Поддержка остаётся условием финальной приёмки, а не утверждённой возможностью движка.

## Подходы

1. Рефакторинг Django + отдельные workers: проще миграция, не выбран пользователем.
2. Django + отдельный сервис просмотра: добавляет границу сервисов, не выбран.
3. Полная замена backend/frontend с последовательным переносом функций: выбран пользователем. Дороже по parity/migration, позволяет разделить чтение, сохранение и конвертацию.

Go/Svelte рассматривались и отклонены. Выбран TS/Fastify + React. Отказ от React не требуется; ограничивается объём клиентской работы.

## Предложения архитектора, требующие утверждения этим документом

- SQLite WAL для первого выпуска; отдельная новая база `yourwiki-v2.sqlite3`, старую Django-базу не переписываем на месте.
- Локальная копия каждого принятого/опубликованного оригинала обязательна; объём диска определяется данными и историями, не RAM.
- Один процесс HTTP и один worker, durable jobs в SQLite, по одному тяжёлому преобразованию одновременно; дополнительный Redis не требуется.
- SSE для событий каталога, публикации, ACL и фоновых статусов; WOPI и существующий CRDT-протокол для своих задач.
- React SSR начального HTML, ограниченная hydration, нативные контролы и динамическая загрузка редакторов.
- Только доверенные устанавливаемые администратором плагины первого поколения. Исполнение произвольного недоверенного кода вне объёма.
- Анимации выключены по умолчанию, выбор сохранён в аккаунте; системный reduced-motion имеет приоритет.

## Процессы и границы

`apps/server`: HTTP/API/SSR, authentication, ACL, каталог, WOPI, download/upload orchestration, SSE. Не выполняет тяжёлую конвертацию или синхронный обход облака для показа страницы.

`apps/worker`: durable jobs, получение облачных originals, выдача/отзыв grants, preview generation, cloud trash, reconciliation неизвестных операций. Преобразователи запускаются изолированными дочерними процессами с memory/time/output limits.

`apps/web`: React shell, viewers и настройки. Canvas/draw.io/PDF загружаются отдельными chunks. Collabora iframe управляется отдельным компонентом.

`packages/contracts`: схемы DTO/ошибок/events. `database`: migrations/repositories. `storage`: streaming blob API. `save-engine`: durability/conflicts/history. `providers`: adapters. `modules`: ссылки и manifests.

Collabora остаётся отдельным сервисом. Её RAM/CPU входит в общий бюджет, её готовность нельзя объявить равной готовности preview.

## Состояние документа

Три независимых указателя:

- `localRevision`: последний надёжно принятый локальный оригинал/снимок.
- `publishedRevision`: последняя ревизия с полностью подготовленным preview.
- `providerRevision`: последняя подтверждённо доставленная ревизия и fingerprint провайдера.

PreviewManifest связывает documentId, localRevision, sourceDigest, converterVersion, artifact digests и schemaVersion. Артефакты immutable. Published pointer обновляется короткой транзакцией только после fsync оригинала, записи файлов preview и manifest.

Состояния подготовки: receiving, queued, preparing, ready, failed. Непубликованный файл видит uploader и администратор в списке обработок; читателям он не доступен. Ошибка показывает retry/recovery, оригинал не удаляется. Для форматов без визуального представления минимальным preview считается готовая карточка метаданных с размером/типом и доступными действиями; это предложение исключает вечное ожидание архивов.

Редактор открывает последнюю localRevision, а preview может относиться к publishedRevision. Если они различаются, показывается статус подготовки обновления. Нельзя незаметно привязать WOPI к устаревшему preview. Событие preview.published содержит точную revision.

Autosave не ждёт preview: durable локальные правки отображаются редактору немедленно. Читатели получают новый preview после подготовки. Очередь конвертации объединяет лишние промежуточные задания, но не удаляет нужные историю/recovery.

## Протокол сохранения

1. Проверить аккаунт, effective ACL, base revision и lease; принять поток во временный файл с лимитами.
2. Завершить blob, вычислить digest, fsync и атомарный rename на том же диске. До подтверждения клиенту записать durable intent и local revision в БД.
3. В одной короткой DB-транзакции создать provider-delivery и preview jobs.
4. Подтвердить «Сохранено в Yourwiki». Внешняя доставка не входит в это подтверждение.
5. Worker сверяет baseline/fingerprint, выполняет provider write и подтверждает providerRevision. Потерянный ACK переводит intent в unknown и запускает reconciliation, а не слепой replay.
6. Обновить статус «Передано в хранилище»; все неоднозначные исходы сохраняют recovery.

Удалённые запросы не держат глобальную write-транзакцию SQLite. На время remote IO используется durable per-document operation lease и повторная проверка local state/ACL перед переходами. Реальные гарантии внешнего CAS зависят от адаптера; ограничения optimistic check/write не скрываются.

Если ACL отозван до отправки pending-правок, правки сохраняются как recovery без записи в original. При внешнем изменении pending-редактирование блокируется конфликтом. Выход не вызывает save; copy/download/reload зависят от export ACL. Непринятый локальный ввод может оставаться только в браузере — нельзя обещать server recovery для него.

## История и форматы

История глобальна и выключена по умолчанию. Revision counter работает всегда. Старый JSON читается и экспортируется совместимо; крупные новые версии хранятся immutable blobs с versioned manifest, чтобы не загружать гигабайты base64 в память. Изменение внешнего формата истории описывается миграцией, не маскируется под прежний JSON.

MD/DOCX/ODS embedded metadata сохраняются где применимы. ACL, queues, sessions и recovery остаются отдельным служебным состоянием. Старые .wiki.zip, .recovery.json и Review anchors поддерживаются совместимыми импортерами.

## ACL и кеш

Сохраняются текущие приоритеты персональных/групповых правил и дерева. Оба admin читают/пишут по прежней политике; только Гигаадмин обходит export restrictions.

Первый выпуск использует глобальный `aclEpoch`, повышаемый в той же транзакции, что изменение policy/group membership/account status/tree/export. Кеш ключуется userId/resourceId/action/aclEpoch. Каждый HTTP/WOPI/event asset access получает актуальный epoch из локальной БД, внешнего запроса нет. Worker переоценивает ACL перед значимым действием. Epoch invalidation публикуется через SSE, но клиентские события не являются защитой.

Приватные blobs/preview доступны только через авторизованный route; public CDN cache запрещён. Долгие streaming responses отменяются при обработанном отзыве доступа где возможно; уже переданные клиенту байты вернуть невозможно. Не обещается защита от скриншотов.

## Провайдеры и центральный аккаунт

Центральный аккаунт выполняет файловые операции, новые подключения не делают оригиналы публичными. Серверные токены не передаются браузеру или Collabora.

Персональные Google/OneDrive/GitHub grants сохраняются для «Открыть оригинал» там, где иначе пользователь не получит доступ. Для пользователей, работающих только внутри Yourwiki, новый runtime не делает профильный OAuth обязательным без потребности в прямом original. Старые identities/grants импортируются; отключение обязательного onboarding — явное изменение маршрутизации, не потеря credentials.

Локальные ACL никогда не берутся из Google. Provider state/versions читаются для синхронизации и конфликтов. Провайдерская выдача/отзыв прав — durable job, ошибки видны и повторяемы. Права облачного владельца нельзя отменить локальным ACL.

Native Google Docs/Sheets/Slides имеют отдельные адаптеры: export/import + revision checks, либо структурированный API при сохранении поддерживаемых операций. Точный выбор и перечень lossless возможностей фиксируются планом адаптера после проверки corpus, не обещаются по одному extension. При потере неподдерживаемой структуры запись отклоняется с объяснением, оригинал сохраняется.

Google trash receipts сохраняют identity и позволяют восстановить файл извне; восстановление возвращает ACL/родителей и не восстанавливает случайно соседние файлы. UI restore только Гигаадмину; внешний restore выполняется системным reconciliation с аудитом источника.

## Просмотр и UI

DOCX/MD: подготовленный безопасный HTML и ресурсы, ограниченная DOM-работа. Таблицы: значения с проверкой актуальности кешированных результатов, merge spans/styles и windowing. PPTX: артефакты слайдов и thumbnails, основной справа, вертикальные thumbnails слева, mobile arrangement. Для полноты представления не требуется вычислять формулы в браузере.

Первое открытие отдаёт готовый HTML+bootstrap; повторные переходы сохраняют shell. Ни весь документ 4 ГБ, ни все невидимые строки не передаются за 0.5 с. Readiness включает видимый контент, нужные стили/шрифты и работу controls; отличие от полной передачи исходника явно отражается в метриках.

PDF.js: range loading, сохранённый derived PDF annotations/forms layer, original и conflict recovery. Canvas/draw.io: текущие форматы, неизвестные поля и совместная работа сохраняются.

Collabora загружается параллельно preview. До ready редактирование preview невозможно. При timeout preview остаётся и доступны retry/recovery. Нельзя показывать два независимых редактируемых экземпляра одного файла. Позиция/фокус восстанавливаются только по подтверждённым возможностям API.

Dashboard редактируют админы: безопасные блоки текста и ссылки на docs/folders/instructions. Recent — отдельные user/document visit records, обновление после реального открытия. Avatar проверяется/перекодируется. Шрифты размещены локально, versioned cache; частные шрифты только с авторизацией/лицензией. Темы/языки/keyboard/touch сохраняются.

## Ошибки и уведомления

Единый ErrorEnvelope: code, messageKey, fieldErrors, retryable, operationId, recoveryActions, requestId. Опасное retryable не выводится из HTTP статуса автоматически: unknown write требует status/reconcile.

Переносятся connecting/reconnecting/saving-local/saved-local/syncing/synced/conflict/denied/unknown, изменившийся original, неподтверждённые grants, превышение лимита, expired CSRF/session, WOPI/lock/lease, loading timeout, error component/font/image, PDF stale layer и clipboard fallback. Уведомления содержат осмысленное действие и не теряют ввод.

## Миграция и обновления

Разработка в том же репозитории без замены production entrypoint до parity. Новый runtime запускается отдельным Compose profile на другом порту; legacy продолжает обслуживать пользователей. Dual writing запрещён.

Importer читает backup старой БД/файлов/secret/journal в новую БД и local blobs. Manifest миграции содержит IDs/digests/counts и receipts; повторный запуск идемпотентен. Нужны проверки паролей и Fernet interoperability, а не только копирование строк.

На cutover остановить приём записей, перенести последний delta и pending/journal, подготовить обязательные previews, проверить identities/digests и роли, переключить один backend. Незавершённые editing sessions не удаляются: перенос state или явное согласованное завершение с recovery. Вопрос совместимости старых browser session cookies решает отдельный migration plan без тихого logout.

После новых записей rollback требует переноса delta назад либо восстановления согласованного snapshot с явно согласованной обработкой новых данных. `git checkout` не является rollback базы.

Дальнейший путь пользователя: git update + Docker rebuild/recreate; migration ledger и converter versions позволяют обновлять движки без потери originals. Локальные config/данные вне tracked файлов. Backup включает БД, encryption key, local originals, history/PDF/recovery, write journal.

## Проверка и неопределённости

Неизвестные возможности 4 ГБ или native Google round-trip не считаются реализованными до подтверждения. При провале обязательной приёмки выпуск блокируется и требуется пересогласование, а не удаление сценария из тестов.

Первый performance report фиксирует реальный RTT, документ corpus и одновременные офисные сессии. Готовность Collabora и страницы измеряются отдельно. p50/p95/p99 и observed max публикуются вместе с условиями; абсолютный максимум для произвольного интернета невозможен.

Начальный ресурсный режим: одна тяжёлая конвертация, ограниченные RAM caches, ограничение idle office sessions. Конкретные лимиты задаются измерениями, не выдумываются как гарантированный бюджет.

Builder самостоятельно выбирает совместимые stable версии зависимостей, библиотеки SQLite/password/session, формат внутренних typed contracts и инструменты тестов; фиксирует их в подробных планах. Не меняет смысл ACL, публикации, ошибок, лимитов, миграции и обязательной функциональной совместимости.

## Критерии завершения

Полная acceptance matrix пройдена, original content/IDs/ACL/pending сохранены, cloud scenarios проверены отдельно от mocks, производительность измерена на целевой конфигурации, backup/restore/cutover отрепетированы. До этого старый runtime не удаляется и переписывание не объявляется завершённым.
