# Google Drive через rclone

Рабочее подключение сохраняет provider `google`, ID источников и адреса документов YourWiki. Это идентичность источника, а не выбор транспорта. В Docker rclone является файловым транспортом по умолчанию: `compose.yaml` задаёт `YOURWIKI_DRIVE_TRANSPORT=rclone`, а `install.sh` устанавливает rclone/FUSE и создаёт host-side `yourwiki-rclone-drive.service`. Для явного fallback используется `YOURWIKI_DRIVE_TRANSPORT=api` или `./install.sh --no-rclone`. В rclone-режиме отсутствие mount — ошибка, автоматического возврата к старому API-адаптеру нет.

- `manager-main.ts` запускает mount для каждого авторизованного подключения. Авторизация берётся из зашифрованной базы; временный rclone.conf имеет права 0600. После смены авторизации mount перезапускается. Обновлённый refresh token сохраняется с проверкой исходной авторизации.
- systemd запускает mount до web/provider и проверяет его готовность. Локальный CAS, база, история и staging лежат на настоящем локальном диске, вне FUSE. Потеря mount не превращает пустой каталог в хранилище.
- Каталог и новые файлы обслуживает `RcloneStorageWorker`. Идентификаторы папок берутся из списка родителя: rclone stat каталога не возвращает ID. Журнал папок позволяет продолжить создание после сбоя.
- Чтение идёт из mount со сверкой удалённых размера/MD5 и метаданных до/после чтения. Устаревшие кешированные байты не подтверждаются. Свежий каталог (до 60 секунд) используется только как подсказка для пропуска неизменившихся фоновых проверок; фоновый скан обновляет его каждые 5 секунд. При чтении изменённого файла private Unix RPC выполняет vfs/forget и vfs/refresh для нужного каталога. В рабочем mount кеш атрибутов ядра отключён; публичный RC-порт не открывается.
- Сохранение сначала проверяет полные байты в локальном staging, затем вызывает rclone copyto для того же оригинала. Подтверждение требует прежнего Google ID и правильного MD5/размера. Новые файлы создаются с `--immutable`; файлы передаются потоково, без загрузки целиком в память.
- Известный ID родительской папки передаётся rclone напрямую: вложенный путь не приходится заново искать от корня при каждой операции.

## Что осталось через Google API

OAuth/проверка аккаунта, первоначальный выбор/создание корневой папки, управление облачными правами/запретом экспорта, точечная корзина и восстановление. Старые воркеры API-чтения, discovery/import, начальной загрузки, watch, lifecycle и repair не запускаются в рабочем цикле rclone. Универсальное хранилище/резервные копии тоже используют rclone.

rclone сам использует Drive API внутри. Это замена собственного файлового API-адаптера, а не отказ от протокола Google.

## Ограничения

`rclone copyto` не предоставляет If-Match для удалённой версии. Система проверяет свежий baseline перед записью и сохраняет неопределённые результаты/локальные байты, однако остаётся окно гонки между проверкой и загрузкой при редактировании непосредственно в Google. Нельзя заявлять атомарный CAS между Google Docs и YourWiki.

Каталог допускает обычные двоичные файлы и нативные Google Docs/Sheets/Slides. Для нативных объектов rclone предоставляет экспорт DOCX/XLSX/PPTX: размер заранее неизвестен (`-1`), MD5 отсутствует. Нативный экспорт читается потоковой командой `rclone cat`, поскольку FUSE может представлять неизвестный размер как нулевой. Поток ограничен лимитом документа; неполный или пустой ZIP отклоняется. MIME/ID/время изменения сверяются до и после чтения. rclone возвращает MIME экспорта, поэтому оригинальный тип берётся из `Metadata.content-type`; прочие метаданные аккаунта в каталог не сохраняются. Отдельный fingerprint `rclone-drive-native-v1` сохраняет Google ID и не разрешает двоичную запись поверх нативного оригинала. Collabora открывает экспорт для просмотра; редактирование оригинала доступно через «Открыть оригинал». Изменения Google отслеживаются тем же каталогом и входящей синхронизацией. Преобразование оригинала в двоичный файл не выполняется. Особенности экспорта: https://rclone.org/drive/#import-export-of-google-documents.

Тестовое подключение `rclone-test` отключено по запросу пользователя 7 ноября 2026. Его mount/bridge остановлены и отключены от автозапуска, startup-зависимости web/provider от теста удалены. Все созданные тестовые папки перемещены в корзину на Drive и скрыты в YourWiki. Единственный активный корень `/` — папка `Yourwiki` того же аккаунта, через production rclone. Google-запись подключения хранит OAuth/идентичность исходников; отдельного активного файлового API-корня нет.

## Проверка

`node apps/server/test/rclone-transport.test.ts` — валидация путей, миграция 68→70, отсутствие скрытого API fallback, ID/MD5, устаревшая запись, кеш и очистка staging.

Операторская проверка (создаёт отдельное QA-поддерево):

```
YOURWIKI_RCLONE_ACCEPTANCE=yes node apps/server/test/live/rclone-drive-acceptance.ts /absolute/workspace
```

Проверяет вложенные папки, создание/сохранение Markdown/Office/Canvas/Drawio, прежний ID, внешнее изменение, отклонение устаревшей записи, корзину/восстановление и foreign_key_check. Результат содержит реальные задержки до подтверждения Drive, а не только локальной записи.
