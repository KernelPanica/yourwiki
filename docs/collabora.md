# Collabora Online в Yourwiki

Collabora добавляет полноценный офисный редактор внутри интерфейса Yourwiki: форматирование, стили, таблицы, изображения, колонтитулы, разметку страниц, комментарии и совместное редактирование. Доступные команды определяет установленная версия Collabora. Это отдельный офисный движок; полное совпадение всех функций Microsoft Word или Google Docs не гарантируется.

## Подключение с Docker и HTTPS

В `.env` в корне репозитория добавьте адрес вашего сайта:

```dotenv
COLLABORA_URL=https://wiki.example.com/collabora
COLLABORA_WOPI_URL=https://wiki.example.com
```

Укажите реальный публичный адрес: контейнер Collabora должен иметь возможность обращаться к Yourwiki по этому адресу. Не используйте localhost для WOPI: из контейнера он указывает на сам контейнер. Если используется внешняя Collabora, настройте также `COLLABORA_INTERNAL_URL` — адрес её discovery, доступный приложению. При запуске нашего Compose overlay внутренний адрес устанавливается автоматически.

В HTTPS-блок Nginx для того же сайта включите содержимое [docker/nginx-collabora.conf](../docker/nginx-collabora.conf). Сохраните существующий основной прокси Yourwiki. В примере используются порты 3000 для приложения и 9980 для Collabora; при изменении портов поправьте оба конфига. Префикс `/collabora` должен сохраняться при проксировании.

```bash
sudo cp docker/nginx-collabora.conf /etc/nginx/snippets/yourwiki-collabora.conf
# Добавьте внутри HTTPS server {}:
# include /etc/nginx/snippets/yourwiki-collabora.conf;
sudo nginx -t
sudo systemctl reload nginx

docker compose -f compose.yaml -f compose.collabora.yaml up -d --build web collabora
```

Для запуска и обновления самого сервиса Collabora указывайте оба Compose-файла (`-f compose.yaml -f compose.collabora.yaml`). Основной compose.yaml также передаёт настройки Collabora из .env: обычное обновление web не отключает уже подключённый редактор. Если Collabora запущена вне этой Docker-сети, укажите её внутренний адрес в COLLABORA_INTERNAL_URL.

Overlay использует Collabora CODE 26.04.5.1 с закреплённым digest образа; обновление образа выполняется явно через `COLLABORA_IMAGE`. CODE — Community Development Edition; для производственных требований и поддержки оцените поддерживаемую редакцию [Collabora Online](https://www.collaboraonline.com/code/).

Проверки после запуска:

```bash
curl -f https://wiki.example.com/collabora/hosting/discovery
docker compose -f compose.yaml -f compose.collabora.yaml ps
```

Затем откройте DOCX через кнопку редактирования в Yourwiki. Полноэкранный режим и проводник управляются оболочкой Yourwiki. Для новых документов формат DOCX уже используется по умолчанию.

## Файлы, права и сохранение

Редактор применяется к документам DOCX, Markdown, обычным таблицам ODS и новым презентациям PPTX. В форме создания выберите «Презентация»: Yourwiki создаст первый слайд и откроет презентацию в Collabora. Презентации сохраняются как стандартные PPTX, включая слайды, изображения и заметки докладчика.

Загруженные офисные файлы открываются в Collabora без предварительного преобразования: DOC/DOCX/DOCM/DOTX/DOTM, ODT/OTT/ODM/OTH/FODT/RTF, XLS/XLSX/XLSM/XLSB/XLTX/XLTM/XLA, ODS/OTS/FODS, PPT/PPTX/PPTM/POTX/POTM/PPSX, ODP/OTP/FODP, ODG/FODG, TXT/MD/CSV/TSV/DIF/SLK/DBF. Формат должен быть объявлен установленной Collabora в discovery; поддержка конкретных возможностей зависит от движка. Сохраняются именно байты, возвращённые Collabora. Текстовые форматы принимаются в UTF-8. Кнопка скачивания исходного офисного файла также возвращает сохранённые байты без повторного создания упрощённой версии.

 Нативные Google Sheets также открываются в Collabora: Google экспортирует таблицу в ODS, а сохранённый редактором ODS импортируется обратно в тот же объект Drive. ID файла, ссылка оригинала и выданные провайдером права сохраняются. Обратный импорт заменяет полное содержимое таблицы, как описано в [Drive API](https://developers.google.com/workspace/drive/api/guides/manage-uploads). Специфичные функции Google могут отличаться при преобразовании в ODS и обратно; на странице редактора показан этот режим. Текущая версия провайдера проверяется перед сохранением. Если результат записи неизвестен и повторный экспорт не совпадает с отправленными байтами, Yourwiki сохраняет копию и показывает конфликт вместо повторной перезаписи. PDF, Draw.io и Canvas сохраняют свои редакторы. Нативные Google Docs/Slides этим адаптером не редактируются: загрузите экспортированный офисный файл. При пустом `COLLABORA_URL` используются прежние редакторы.

Yourwiki реализует WOPI: Collabora получает файл и отправляет полный изменённый офисный файл обратно. Содержимое сохраняется непосредственно в подключённом хранилище; сложное форматирование не проходит через упрощённое текстовое представление Yourwiki. Настройка истории продолжает применяться к этим сохранениям. Размер файла задаёт администратор в настройках сайта: положительное число МиБ либо 0 без ограничения. WOPI и Nginx применяют эту политику.

Каждому пользователю выдаётся отдельный подписанный токен на 8 часов. Каждый запрос повторно проверяет действующий аккаунт и текущие права read/write. Пользователь с read открывает документ без права записи. Провайдерские токены не передаются редактору. Все участники открывают одну сессию файла и могут редактировать вместе.

Сессия активна 30 минут после последнего обращения; открытая страница проверяет оригинал и продлевает сессию каждые 30 секунд. При внешнем изменении чистый редактор переоткрывается с новой сессией. Если есть локальные правки, появляется конфликт: скопируйте их или скачайте текущую копию перед уходом. Уход со страницы не запрашивает дополнительное сохранение. Перед первым переходом сохраните и закройте старые редакторы Yourwiki для этого файла. Пока работает Collabora, запись через прежний редактор и API блокируется, чтобы два разных механизма не перезаписывали друг друга.

При конфликте с изменением оригинала или ошибке провайдера отправленные Collabora байты сохраняются как восстановительная копия в SQLite. На странице редактора появляется «Скачать копию для восстановления»; скачать её может автор последнего сохранения или администратор. Оригинал не заменяется при обнаруженном конфликте. После восстановления связи повторное успешное сохранение удаляет аварийную копию. Если оригинал изменён независимо, скачайте копию и согласуйте варианты; автоматическое слияние таких бинарных файлов не выполняется. Сессия с аварийной копией продолжает блокировать старый редактор даже после истечения времени активности.

Комментарии внутри Collabora сохраняются в офисном файле. Ранее созданные комментарии и предложения отдельного слоя Yourwiki автоматически в офисный файл не переносятся.

Nginx отключает access log для WOPI и Collabora: подписанные токены не должны попадать в журналы URL. Если добавляете другой прокси, примените то же правило.

## Проверка разработчиком

```bash
pytest -q tests/test_collabora.py tests/test_write_recovery.py tests/test_save_sessions.py
```

Реальный браузерный тест проверяет открытие DOCX в CODE и запись введённого текста обратно в хранилище. Он запускается отдельно с `RUN_COLLABORA=1`, ожидает Collabora на `127.0.0.1:19980` с `net.service_root=/collabora`, отключённым SSL и разрешённым WOPI-адресом `http://host.docker.internal:18080`. Контейнеру нужен `--add-host host.docker.internal:host-gateway`; приложение теста слушает порт 18080.

```bash
RUN_COLLABORA=1 pytest -q tests/browser/test_collabora_editor.py
```

## Свободные шрифты

Compose передаёт `--o:remote_font_config.url=${COLLABORA_WOPI_URL}/office/fonts.json`. Публичный каталог содержит проверяемые SHA-256 отпечатки локальных TTF; Collabora загружает их без учётных данных и включает в список шрифтов. Подробности, аналоги Times New Roman/Impact и лицензии описаны в README.

Remote font configuration requires HTTPS, even when CODE itself runs behind an HTTP reverse proxy. For the optional `test_real_collabora_offers_open_fonts` browser test, configure the test CODE container with `--o:remote_font_config.url=https://YOURWIKI/office/fonts.json` pointing to an accessible deployed catalogue. For local HTTP WOPI tests use `ssl.termination=false`.

Оригинальный Impact устанавливается отдельно через `python3 docker/install_impact.py --accept-eula` (нужен `cabextract`). Compose монтирует `instance/office-fonts` или `COLLABORA_CUSTOM_FONTS` в системный каталог шрифтов CODE и его шаблон рабочего окружения. TTF не публикуется в `/office/fonts.json` и не включается в исходники. См. README для условий EULA и проверки контрольных сумм.

Полный свободный каталог Google Fonts устанавливается командой `.venv/bin/python docker/install_google_fonts.py` на хосте. Локальные файлы и лицензии находятся в `instance/office-fonts` и исключены из Git. Compose overlay монтирует каталог также в Yourwiki; `/office/fonts.json` сообщает Collabora список и контрольные суммы всех зарегистрированных файлов. Collabora автоматически подгружает каталог, поэтому для добавления шрифтов не требуется прерывать открытые документы. После первоначальной загрузки переоткройте документ для обновления списка. Для тысяч шрифтов задан `ulimits.nofile` (soft 65536, hard 1048576); маленький лимит приводит к `Too many open files` при регистрации. Нативные редакторы используют тот же каталог, загружая семейство только после выбора. Сохранена кириллическая версия Anton. Проверка на рабочем сервере подтвердила наличие Alegreya, Lobster, Montserrat, Noto Sans, Playfair Display, Roboto Slab, Anton и Impact в меню настоящей Collabora.
