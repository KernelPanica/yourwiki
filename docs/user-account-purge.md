# Permanent user removal

Only Giga admins can purge a user from Settings → Trash. Moving to Trash keeps the Google identity reserved for restoration; permanent purge deletes the identity row, sessions/Office tokens, pending identity/connect/registration attempts, reset links, preferences/avatar, memberships/invitation privileges, presence/visits and personal ACL entries. Invitations issued by the deleted user are revoked. A minimal anonymized user ID remains for document/history/audit references; authored files and global storage connections are retained.

The deleted user's verified Google email is retained only in a durable revocation task while tracked Drive grants are being removed. The existing provider worker uses the central storage credentials, verifies the original belongs to the configured root, removes matching user permissions and reads them back. Until confirmation, the recipient is fenced from receiving new app grants, even if a new YourWiki account registers with the same Google identity. After confirmation, recipient grants are deleted, legacy receipt personal fields are redacted through a narrowly scoped SQL trigger and the task's email is erased. No personal Google Drive refresh tokens were stored by the identity flow.

Settings → Trash shows pending, blocked and complete counts, sanitized errors, refresh and retry controls. Only Giga admins can view/retry; mutation requests require current authentication, exact origin and CSRF. Workers automatically retry failures and preserve evidence for uncertain outcomes. A lost DELETE acknowledgement is reconciled by a fresh permissions read; creation/update ambiguity outside permanent purge remains fenced.

Owner permissions cannot be deleted: transfer ownership on Google Drive first, then retry. Disabled/disconnected storage and permission/API failures remain visibly blocked. The app does not delete the Google account itself, unrelated Google files, public-link permissions or global storage credentials. Revocation concerns individual permissions on Drive originals managed by YourWiki. Already-purged users are migrated through the same cleanup path without changing active identities. Workspace backups created before removal retain their historical snapshot.
