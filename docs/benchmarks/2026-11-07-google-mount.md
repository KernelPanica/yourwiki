# Google Drive mount: изолированный прототип и замеры

Дата: 7 ноября 2026. Тест выполнен на том же сервере, где работает YourWiki (Linux/Debian, 3 доступных CPU, около 8 ГБ RAM). Рабочее хранилище и сервисы не переключались.

Сделан запускаемый прототип файлового подключения через rclone/FUSE. Код: `apps/server/test/live/google-mount-benchmark.ts`. Машиночитаемые результаты: `2026-11-07-google-mount.json` рядом с этим отчётом.

## Запись до подтверждения в Google

По 3 записи каждым способом для каждого размера. Порядок способов чередовался. В таблице медиана и полный диапазон; это небольшой эксперимент, не оценка p95.

| Размер | Текущий механизм YourWiki | rclone mount | Отношение медиан |
|---|---:|---:|---:|
| 64 КиБ | 5,28 с (4,21–5,77) | 2,57 с (2,54–2,57) | mount быстрее в 2,06 раза |
| 8 МиБ | 8,56 с (8,34–9,14) | 3,53 с (3,34–4,03) | mount быстрее в 2,42 раза |

Это время от начала локальной записи до независимого подтверждения размера/MD5 в Google и скачивания содержимого с проверкой SHA-256. Результат не ограничен возвратом из `write`/`close` или появлением файла в локальном кеше. Опрос подтверждения имеет шаг 250 мс плюс время запроса Google.

Локальная фиксация отдельно: медианы YourWiki 4 мс/66 мс, mount 269 мс/252 мс для 64 КиБ/8 МиБ соответственно. Быстрый локальный ответ не означает завершённую доставку.

Текущий механизм запускался через реальные DocumentService/GoogleStoragePush с актуальным исправлением повторной проверки метаданных. Время ожидания общей очереди, генерации предпросмотра и работы интерфейса в измерение не включено. Он дополнительно проверяет права, принадлежность источника, стабильность удалённой версии и прочитывает содержимое перед привязкой. Mount в этом прототипе ещё не реализует эквивалентные гарантии YourWiki: различие проверок является частью измеряемой разницы, а не доказательством, что равнозначная production-интеграция сохранит весь выигрыш.

Тестовые файлы — случайные бинарные данные одинакового размера, обычные файлы Google Drive. Нативные Google Docs/Sheets/Slides и преобразование форматов не тестировались.

## Чтение и внешние изменения

- Чтение 8 МиБ через mount, холодный кеш: 783 мс (один замер).
- Два повторных чтения: 83 и 80 мс. Во время измерения также проверялась контрольная сумма.
- После внешней записи через Drive API mount увидел новые байты через 2,975 / 0,930 / 2,933 с после ответа Google; медиана 2,933 с. Это проверка обычного файла, не редактор Google Docs.
- Пиковый RSS процесса rclone по выборкам каждые 500 мс: 104,9 МиБ; суммарное процессорное время: 0,81 с. Это нагрузка rclone в данном коротком тесте, без ресурсов Node/Google API/остального сайта; не длительный нагрузочный тест.

## Конфигурация и изоляция

rclone v1.76.0, официальный архив проверен по опубликованной SHA-256. FUSE helper извлечён из пакета в частную тестовую директорию, без системной установки. Параметры: `--vfs-cache-mode full --vfs-write-back 0s --poll-interval 2s --dir-cache-time 1m --attr-timeout 1s --buffer-size 4M --vfs-cache-max-size 128M --transfers 2`.

Одна помеченная тестовая папка находилась вне рабочего корня YourWiki. База production открывалась только для чтения конфигурации, операции приложения шли через отдельную временную БД. Rclone получил только короткоживущий access token во временном файле с правами 0600, без production refresh token. После теста mount отключён, процесс завершён, тестовая папка перемещена в корзину Drive, временные конфигурация и кеш удалены. Тестовый бинарник оставлен для повторных запусков; фоновой службы mount нет.

## Вывод

Прототип показывает заметный выигрыш в отправке обычных файлов и быстрое чтение из кеша. Это обоснование для следующего этапа — отдельного адаптера хранения YourWiki с сохранением прав, идентичности исходного объекта, обработки конфликтов и подтверждения доставки. Подменять им текущее хранилище без этих проверок по результатам одного теста нельзя считать проверенной интеграцией.

Повторный запуск на тестовом сервере требует явных переменных `YOURWIKI_LIVE_CREDENTIAL_WORKSPACE`, `YOURWIKI_RCLONE_TOOLS` и `YOURWIKI_LIVE_CREATE_TEST_FOLDER=yes`; обычный запуск без них отказывается работать. Используемый access token должен оставаться действительным на протяжении короткого теста. Не запускать параллельно несколько экземпляров.
