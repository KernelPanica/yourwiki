# Скорость установленной тестовой интеграции rclone

7 ноября 2026. Измерено на сервере с постоянно работающими `yourwiki-rclone-test`, `yourwiki-rclone-test-bridge` и штатными web/provider/preview. Это повторный тест после интеграции с приложением, а не прежний изолированный benchmark прямого mount. Рабочие источники не переключались.

## Создание и изменение файлов

По три повтора на размер и операцию. Значения в таблице: медиана, в скобках диапазон всех трёх результатов. Создание проходило через реальный DocumentService, далее штатный bridge. Сохранение — DocumentService.save и штатная очередь provider worker. Очереди не ускорялись вручную.

| Операция | Размер | Фиксация в локальном хранилище YourWiki | Подтверждение local provider/VFS | Подтверждение фактических байтов в Google |
|---|---:|---:|---:|---:|
| Создание | 64 КиБ Markdown | 13 мс (12–153) | 2,77 с (2,52–2,92) | **3,06 с (2,87–3,17)** |
| Сохранение изменений | 64 КиБ Markdown | 16 мс (13–18) | 0,27 с (0,27–2,77) | **2,03 с (1,95–4,52)** |
| Создание | 8 МиБ binary | 89 мс (87–95) | 4,11 с (3,85–4,36) | **4,40 с (4,15–4,65)** |
| Сохранение изменений | 8 МиБ binary | 100 мс (88–116) | 2,87 с (2,35–3,11) | **5,16 с (4,63–5,38)** |

Последний столбец подтверждён независимым запросом Drive API по размеру и MD5 содержимого. Время ответа API входит в измерение; опрос каждые 250 мс плюс сетевое время. Возврат локального сохранения/изменение provider_revision сами по себе не считаются доставкой в Google. В этой серии нет повторного скачивания для SHA-256 — оно проверялось в предыдущем acceptance/изолированном benchmark.

Замеры начинаются с вызова серверного DocumentService. В них входят обычные фоновые очереди и запись rclone, но не передача от браузера на сервер, задержка debounce редактора или отрисовка страницы. 64 КиБ — искусственный текст, 8 МиБ — случайные бинарные данные. Это небольшая серия; p95/нагрузочную устойчивость по ней оценивать нельзя.

## Чтение

8 МиБ, с проверкой SHA-256 в измеряемом участке:

| Откуда | Состояние кеша | Результаты |
|---|---|---:|
| Локальное CAS YourWiki | Прогретое | 43 / 49 / 75 мс, медиана **49 мс** |
| rclone mount | Холодное | **903 мс**, один файл/один замер |
| rclone mount | Прогретое | **98 / 78 мс** |

Холодный файл создан непосредственно через Drive API и до измерения его содержимое не читалось через mount; ожидалось только появление имени в каталоге. Поэтому быстрый mount-кеш не означает ускорение уже существующего локального кеша YourWiki.

## Изменение на стороне Google

Три последовательных обновления обычного Markdown-файла через Drive API. Время отсчитывается от успешного ответа Google о записи:

| Где появились новые байты | Три замера | Медиана |
|---|---|---:|
| В mount | 2,17 / 3,19 / 3,12 с | **3,12 с** |
| В основной версии документа YourWiki | 13,23 / 28,33 / 28,27 с | **28,27 с** |

Собственно запрос изменения в Google занимал 1,32–1,45 с; он не включён в эти два интервала. Применение в YourWiki подтверждалось новой checksum основной document_version и совпадением provider_revision/local_revision; отрисовка редактора не измерялась.

**Узкое место внешней синхронизации — опрос local provider в YourWiki.** Rclone опрашивает изменения каждые 2 с, но `IngressScheduler` для local источника использует пассивный интервал 30 с: признак активного документа в текущем SQL ограничен `c.provider='google'`. Это соответствует наблюдаемому ожиданию 13–28 с. В ходе измерения код/интервалы не менялись.

Нативные Google Docs/Sheets/Slides и редактирование через их UI в этой серии не проверялись.

## Ресурсы и итог

- Пиковый RSS процесса rclone по выборкам раз в 500 мс: **109 МиБ**.
- CPU самого rclone за окно **126 с**: **3,83 процессорной секунды**. Это не суммарная нагрузка Node/preview/всего сервера.
- Все 12 операций записи подтверждены на Google; все три внешних обновления применились в YourWiki.
- После измерения все пять служб активны, HTTPS `/ready/` возвращает ready.
- Тестовые объекты оставлены в отдельной подпапке «Замеры скорости …» внутри тестового хранилища, ID `3159f90f-5eda-4782-9e73-140e2c82394e`. Пользовательские файлы вне тестового источника не изменялись.

Результаты: запись в Google занимает обычно 2–5 с, локальное сохранение — десятки миллисекунд. Приоритет для ускорения обратного направления — убрать 30-секундное ожидание опроса local provider, сохранив ограничение нагрузки и конфликтные проверки. Этот отчёт фиксирует измерение; оптимизация интервала в него не входит.

Сырые результаты и агрегаты: `2026-11-07-rclone-installed.json` рядом с отчётом. Воспроизводимый opt-in сценарий: `apps/server/test/live/rclone-installed-benchmark.ts`; запуск с `YOURWIKI_RCLONE_BENCHMARK=yes`, путями рабочего пространства и settings тестового mount. Сценарий создаёт только свою новую подпапку внутри `rclone-test`.
