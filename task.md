## Доработать работу с файлами и синхронизацией в YourWiki

### Описание

Необходимо переработать механизм работы с файлами в YourWiki, чтобы система корректно работала с удалёнными источниками, большими файлами, правами доступа, ревизионированием и одновременным редактированием.

Основная цель — сократить количество служебного состояния, хранящегося отдельно от файлов, и сделать сам файл основным источником данных там, где это возможно.

### Требования

1. Добавить возможность открыть исходный файл на удалённом источнике.

Для файлов, подключённых из внешних источников, пользователь должен иметь возможность перейти к оригиналу файла в соответствующем сервисе.

Например:
- Google Drive;
- Git-репозиторий;
- WebDAV;
- другой поддерживаемый удалённый источник.

Кнопка или ссылка должна отображаться только в том случае, если для файла известен исходный URL или иной способ открытия оригинала.

2. Исправить загрузку больших файлов через Nginx.

Текущая конфигурация не должна блокировать загрузку файлов допустимого для YourWiki размера.

Необходимо проверить и при необходимости изменить:
- `client_max_body_size`;
- таймауты;
- проксирование тела запроса;
- лимиты backend-приложения.

3. Сделать ревизионирование файлов опциональным.

Для файла, папки, пространства или источника должна существовать возможность отключить хранение истории изменений.

При отключённом ревизионировании новые версии файла не должны создавать отдельную историю изменений.

При включённом ревизионировании существующее поведение должно сохраняться.

4. Перенести служебные данные из отдельных JSON-файлов в сами файлы там, где это возможно.

Метаданные документа не должны без необходимости храниться в отдельных JSON-файлах.

Для форматов, позволяющих хранить метаданные непосредственно в содержимом, следует использовать встроенный механизм метаданных.

Например, для Markdown может использоваться front matter.

Служебная база данных или отдельное хранилище допускаются только для информации, которую невозможно или нецелесообразно хранить непосредственно в файле.

5. Добавить синхронизацию сессии редактирования.

Если один и тот же файл открыт на редактирование несколькими клиентами, система должна учитывать существующие активные сессии.

Необходимо как минимум предотвращать незаметную перезапись более новой версии файла устаревшей версией.

Допустимая реализация для первого этапа:
- optimistic locking;
- версия/ETag файла;
- уведомление о конфликте;
- предложение обновить содержимое перед сохранением.

Полноценное collaborative editing в реальном времени в рамках этой задачи не требуется.

6. Реализовать наследование прав от папок.

Все файлы и подпапки, доступные через YourWiki, должны наследовать права доступа родительской папки, если для них не определены собственные права.

Наследование должно работать рекурсивно.

При изменении прав родительской папки объекты с наследуемыми правами должны автоматически использовать новые значения.

Явно заданные права объекта должны иметь приоритет над наследуемыми.

7. Поменять формат таблиц на нативный формат google sheets. (можно .ods)

### Критерии приёмки

- У файла из удалённого источника существует действие «Открыть оригинал», если источник предоставляет соответствующую ссылку. (Но доступ к документу должен иметь только аккаунт, с которого подключался маунтпоинт) Права у провайдера: не делать файл публичным; кнопку видят читатели Yourwiki.
- Переход по этому действию открывает именно исходный объект в удалённом сервисе.
- Файл размером в пределах установленного лимита YourWiki успешно загружается через production-конфигурацию Nginx.
- При превышении лимита пользователь получает понятную ошибку, а не необъяснимый `413`, timeout или обрыв соединения, если это вина nginx, то просто сообщить об этом пользователю.
- Ревизионирование можно включить и отключить настройкой. (Отключено по умочанию, ревизионирование полностью переделлать, пусть будет дебликат файла имя.расширение.json с историей изменений)
- При отключённом ревизионировании сохранение файла не создаёт новые ревизии.
- При включённом ревизионировании история изменений продолжает работать.
- Метаданные, которые могут храниться непосредственно в файле, не дублируются в отдельном JSON-файле при отключенном ревизионировании.
- После перезапуска YourWiki необходимые метаданные корректно восстанавливаются из файла или основного хранилища.
- Два клиента не могут незаметно перезаписать изменения друг друга при одновременном редактировании.
- При попытке сохранить устаревшую версию пользователь получает сообщение о конфликте.
- Новый файл или подпапка без собственных ACL наследует права родительской папки.
- Наследование работает на нескольких уровнях вложенности.
- Изменение прав папки применяется ко всем потомкам, использующим наследуемые права при создании.
- Явно заданные права файла или подпапки не перезаписываются изменением родительских прав.
- Существующие файлы после миграции продолжают открываться и редактироваться без потери содержимого.
- Markdown и docx создаются раздельно, но редактируются одинаковым GUI.
- Таблицы создаются с нативным форматом гугл и открываются в google sheets. (если у гугл нет нативного формата, то .ods)
- При перемещении файлы не копируются, а буквально перемещаются в другую папку.
